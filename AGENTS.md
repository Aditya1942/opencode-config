# AGENTS.md — OpenCode Configuration Repository

## Project Overview

OpenCode.ai configuration repository: AI agent skills, plugins, orchestration config.
Runtime: Bun/Node.js. Single dependency: `@opencode-ai/plugin`.
This is a **config-only** repo — no application code, no build artifacts.

## Repository Structure

```
opencode.json            # Agent/model/command/MCP server configuration
plugins/superpowers.js   # Bootstrap plugin — injects skill framework via system prompt
skills/
  superpowers/           # Core workflow skills (TDD, debugging, planning, etc.) — symlinked
  claudepowers/          # Domain skills (code review, frontend, security, etc.)
  team-agents/           # Subagent routing and delegation
.sisyphus/plans/         # Implementation plans (generated by prometheus-lite)
.sisyphus/drafts/        # Draft plans and interview notes
docs/                    # Guides (model management, etc.)
superpowers/             # Upstream superpowers git repo (gitignored, managed independently)
```

## Build / Test / Lint Commands

the `claude` CLI installed and local dev marketplace enabled in settings.

## Code Style

### JavaScript / Plugins

- **ES Modules only** — `import`/`export`. Never use `require()` or `module.exports`.
- **`const` arrow functions** preferred: `const foo = (x) => { ... };`
- **Naming**: `camelCase` for functions/variables, `PascalCase` for plugin exports (e.g. `SuperpowersPlugin`).
- **Formatting**: 2-space indentation. Single quotes for strings. No semicolons at end of lines is acceptable but be consistent within a file.
- **Defensive programming** over broad try/catch — use null checks, early returns, optional chaining (`?.`), nullish coalescing (`??`).
- **Error handling**: Catch narrowly, return safe defaults (e.g. `{ name: '', description: '' }`). Never swallow errors silently unless in bootstrap/non-critical paths (network timeouts, missing optional files).
- **Imports**: Group stdlib (`path`, `fs`, `os`) first, then dependencies, then local. Use `fileURLToPath(import.meta.url)` for `__dirname` equivalent.
- **Types**: JSDoc `@param`/`@returns` annotations for exported functions. No TypeScript in this repo.
- **No hallucinated imports** — only use packages declared in `package.json` (`@opencode-ai/plugin`).

### Skills / Markdown

- YAML frontmatter required: `name` and `description` fields.
- `kebab-case` for directory names (e.g. `systematic-debugging/`).
- Imperative tone. Structure: Overview → When to Use → Checklist → Details → Anti-patterns.
- Skill files are always named `SKILL.md`.

### JSON Configs

- Include `$schema` field where applicable.
- `kebab-case` for agent names and command names (e.g. `explore-fallback`, `write-plan`).
- Agent prompts are inline strings in `opencode.json` — keep them focused.

## Skills

Skills live in `skills/<collection>/<skill-name>/SKILL.md` with YAML frontmatter.

**Iron Law:** If a skill might apply (even 1% chance), invoke it before doing anything else.
Use the `skill` tool — never read SKILL.md files directly.

| Skill | When to Use |
|-------|-------------|
| `brainstorming` | Before ANY creative/feature work (mandatory) |
| `test-driven-development` | Before writing implementation code |
| `systematic-debugging` | When encountering bugs, before proposing fixes |
| `writing-plans` | When you have specs, before touching code |
| `executing-plans` | When you have a written plan to execute |
| `subagent-driven-development` | Independent tasks in current session |
| `verification-before-completion` | Before claiming work is done |
| `using-git-worktrees` | For feature isolation before implementation |
| `dispatching-parallel-agents` | 2+ independent tasks without shared state |
| `code-review` | When reviewing PRs for bugs and quality |
| `security-guidance` | When editing files with security implications |
| `frontend-design` | Building web components, pages, applications |

## Config Change Checklist

When adding, removing, or updating MCPs, skills, commands, agents, plugins, or models, follow the checklist in `docs/config-change-checklist.md` to update all files that track config state.

## Git Conventions

- Small, frequent, atomic commits. Use worktrees for feature isolation.
- **Gitignored**: `node_modules/`, `bun.lock`, `package-lock.json`, `superpowers/`, `.DS_Store`,
  `antigravity-accounts.json`, `antigravity-logs/`, `.env`, `.env.local`, `.openCode/opencode.json`.
- The `superpowers/` directory is a separate upstream git repo — do not commit into it from here.

## Anti-Patterns

1. **Serial collapse** — sequential work when tasks are parallelizable
2. **Spurious parallelism** — subagents without meaningful decomposition
3. **Skipping skills** — rationalizing a task is "too simple" for a skill
4. **Broad try/catch** — use defensive null checks and early returns instead
5. **CommonJS imports** — always ES Modules (`import`/`export`)
6. **Reading skill files directly** — always use the `skill` tool
7. **Hallucinated dependencies** — only `@opencode-ai/plugin` is available
8. **Modifying superpowers/** — it's a separate repo, managed independently
9. **Committing secrets** — `.env`, API keys, account JSON files are gitignored for a reason
